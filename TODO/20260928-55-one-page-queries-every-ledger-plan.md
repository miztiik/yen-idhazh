# Plan 55 - One page queries every ledger

**Last Updated**: 2026-10-02

**Level**: 5 (CLAUDE.md section 6). It adds a member to a persisted vocabulary (`RouteId` on the console band). It widens one persisted contract: `RawDayIndex` gains an optional `bytes` list, one size per listed file, so a browser can price a writer file and check its length before it fetches it (row 2). It adds an entry point to the query door, it publishes more of `state/` and the registry that names it, and it opens a surface where an operator's own text reaches a query engine. The site build writes listings in `RawDayIndex`'s shape into the staged site only, never into `state/` (row 7).

**Chain** (CLAUDE.md section 0d). **Intent**: the owner looks through the project's own recorded data directly - pick the ledgers, pick the days, write the question, read the answer - without waiting for somebody to build a panel for it. **Contract**: section 2 declares every address, shape, name, statement, knob, word and refusal these rows need, checked against `main` at 9cabfa8dd on 2026-10-02, so a worker writes each row with no further decision. **Code**: the seven rows.

Execute per docs/how-to/execute-a-plan.md: one owner carries the plan and delegates a row where delegation pays; keep parallel N = 2 rows in flight as a running pool, refilling a slot the moment a worker returns and never waiting on a merge; serialise merges and re-check each branch against the advanced main; run the browser and build gates one at a time behind the shared gate lock; consult a persona only where two answers would lead to different code; AUTO-merge on green gates where no ESCALATE trigger fired; honor the ESCALATE triggers in section 0. AUTHOR-AND-STOP until the user authorizes.

### 2.4 `ask()`: the signature, and how a buffer becomes a table

Row 2 adds two exports to `frontend/src/lib/data/ledger.ts`, `ask()` and `askCost()`, and their shapes to `slice-shapes.ts`. Everything already there is unchanged.

```ts
/** Run one read-only statement over a chosen set of ledgers and days.
 *  The caller chooses the ledgers and the span; the statement shapes the answer
 *  and never chooses a file. */
export function ask(opts: AskOptions): Promise<AskResult>;

export type AskOptions = {
	/** Non-empty. Each becomes one view of the same name, hyphens and all -
	 *  a statement quotes it as "item-health". */
	ledgers: readonly LedgerName[];
	from: DateStamp;
	to: DateStamp;
	/** One read-only statement. Refused before the engine sees it if it is not. */
	sql: string;
	/** The longest statement `statement.ts` lets through, in characters. */
	maxChars: number;
	/** The most rows the answer holds. Past it `capped` is true and the rows are real. */
	maxRows: number;
	/** The most bytes this call may fetch. Refused before any fetch when the
	 *  indexes say the span costs more. */
	maxFetchBytes: number;
};

/** One column of the answer, as the engine describes it. */
export type Column = { name: string; type: string };

/** What the fetch actually cost, so the page prints a reading and never a guess. */
export type FetchCost = { files: number; bytes: number; alreadyHeld: number; ms: number };

/** What a span will cost before it is paid, from the indexes and the day listings alone,
 *  and how far each selected, published ledger reaches: its newest day that holds a file, packed or listed. */
export type SpanCost = { files: number; bytes: number; unpackedDays: readonly DateStamp[]; through: Readonly<Partial<Record<LedgerName, DateStamp>>> };

export type AskResult =
	| { state: 'ok'; columns: readonly Column[]; rows: Row[]; capped: boolean; read: FetchCost; unpackedDays: readonly DateStamp[] }
	| { state: 'quiet'; columns: readonly Column[]; read: FetchCost }
	| { state: 'missing'; ledger: LedgerName }
	| { state: 'unreachable'; ledger: LedgerName | null; at: DateStamp | null; fault: AskFault }
	| { state: 'refused'; because: AskRefusal };

/** Why an answer did not come. `null`: a file the indexes name did not arrive whole.
 *  A `LedgerFault` other than `not-packed`: a gap in what the site holds. Both name `ledger` and `at`.
 *  `engine`: the query engine did not start in this browser, and `ledger` and `at` are null. */
export type AskFault = Exclude<LedgerFault, 'not-packed'> | 'engine' | null;

/** Why a statement did not run, with the figures its sentence prints (section 2.12, the words table). */
export type AskRefusal =
	| { kind: 'statements'; count: number }
	| { kind: 'not-read-only'; word: string }
	| { kind: 'too-long'; chars: number; max: number }
	| { kind: 'over-ceiling'; bytes: number; files: number; max: number }
	| { kind: 'engine-error'; message: string };

/** What the span would cost, from the indexes and the day listings, fetching no data file. */
export function askCost(ledgers: readonly LedgerName[], from: DateStamp, to: DateStamp): Promise<SpanCost>;
```

**`unreachable` and `refused` carry what their sentences print, and the door writes no sentence.** The page draws section 2.12's words from these fields, so `waiting.ts` stays the one place that holds a state's words. A browser with no WebAssembly exception handling is an engine that did not start (`fault: 'engine'`): telling the two apart would need a change to `engine.ts`, which this plan keeps untouched, and the one sentence for both says what the reader can do.

**`ask` rather than `query`.** The module is already the query door, so `query()` beside `slice()` would put the same word in two jobs one sentence apart (CLAUDE.md section 0b).

**A registered buffer is a file, so `ask()` creates one view per ledger.** The engine mints every registered name - `door/<n>.parquet` from a counter - and a statement cannot name a ledger until something binds the name.

**Why the registered name is not simply the ledger's name.** Not for a security reason first, but an arithmetic one: **one ledger is many files.** Fourteen days of `item-health` is one month file, plus the day files after it, plus the writers' files for the days not packed yet, and five parquet blobs cannot share one name. The minted name names a **file**; the ledger name names the **set**. The view is the one statement that binds the second to the first, and the minting rule then costs nothing, because the name a person types was never going to be the name a file was registered under.

```ts
// For each selected ledger, in order, after `hold()` has returned its names:
//   CREATE OR REPLACE VIEW "item-health" AS
//     SELECT * FROM read_parquet(['door/1.parquet', 'door/2.parquet'], union_by_name = true)
// A month or year file the span reads only some days of gets a read of its own (rule 9):
//   CREATE OR REPLACE VIEW "item-health" AS
//     SELECT * FROM read_parquet(['door/1.parquet'], union_by_name = true)
//       WHERE "covers" >= '2026-08-31' AND "covers" <= '2026-08-31'
//     UNION ALL BY NAME
//     SELECT * FROM read_parquet(['door/2.parquet', 'door/3.parquet'], union_by_name = true)
// For every name in LEDGER_NAMES that this call did NOT select:
//   DROP VIEW IF EXISTS "item-health"
```

### 2.6 The boundary is the browser's, and this plan adds nothing to it

**This is the design plan 51 approved and shipped, unchanged. No row here sets an engine option, pins the engine's version, or pre-loads an add-on** (owner, 2026-09-29).

A database setting would have been a second lock on a door the browser already holds shut, and it would have broken the door on the way: the engine links only DuckDB's core functions and fetches its parquet reader over the network at first use, so a setting that closes the network closes every panel on the console (section 2.1 facts 1 and 2). **A static site's boundary is its content policy. That is how every site does this, and this one is not special.**

**Four controls, and three of them are already on `main`.**

| # | Control | What it stops | Where it lives |
| --- | --- | --- | --- |
| 1 | Only files the door chose are visible: a buffer the page fetched (`registerFileBuffer`), or a year file opened at an address `fetched-bytes.ts` composed from a closed ledger name and an index-checked period (`registerFileURL`, inside `registerAddress()` alone, #1178) | The engine cannot open a file the door did not choose | `engine.ts`, shipped |
| 2 | **Every registered name is minted by the engine** - `door/<n>.parquet` from a counter, never from an index, a `covers` value, a cell or a caller | No fetched text and no typed text can name a file | `engine.ts`, shipped |
| 3 | `connect-src`, which the browser enforces **on the engine's worker as well as on the page**, because the worker starts from a `blob:` bootstrap | Any request to an origin not on the list, from the page or from inside a statement | `asset-base.js` computes each origin and `svelte.config.js` hands the list to `connectSources()`, shipped |
| 4 | The page refuses, before the engine sees it: more than one statement; anything that is not `SELECT`, `WITH ... SELECT`, `DESCRIBE`, `SUMMARIZE` or `EXPLAIN`; and a statement longer than `AskOptions.maxChars`, which row 4 fills from `console.explorer_query_max_chars` | A write, a schema change, and a paste large enough to stop the tab responding | `statement.ts`, row 2 |

**Control 4 is a courtesy, and it is written down as one.** It gives the operator a fast, readable refusal for an obvious mistake, in their own words rather than the engine's. A denylist over a language with function syntax is not a boundary, and **nothing in this plan rests on it**.

**What `connect-src` admits, stated rather than implied.** `connectSources()` in `frontend/asset-base.js` computes it from config. On 2026-10-02 the committed config yields `'self'`, the encoder's two failover origins `https://huggingface.co` and `https://us.aws.cdn.hf.co` (`encoderOrigins()`), and `https://extensions.duckdb.org` (`engineOrigins()`); `visuals.asset_base_url`'s origin joins it when that knob is set, and it is empty today. Row 3 adds `ledger.archive_base_url`'s origin the same way - a reader in `asset-base.js`, joined to the list `svelte.config.js` hands `connectSources()` - and it ships empty. **A statement can read a public file on one of those origins and nowhere else.** That is the whole residual. It is the same exposure every panel on the console already has, it is what a browser can actually enforce, and no row here widens it past the one address the owner asked for.

**The engine takes a caret range, not a pin.** There is no setting whose removal could break a boundary, because no boundary here is a setting.

**What the oracle asserts, and what it deliberately does not.** Row 2 proves the boundary that exists. The first line is the browser check in row 2's gates, because no Node run has a content policy; the other three are the Node oracle:

```
SELECT * FROM read_csv('https://example.invalid/x.csv')   -- the browser refuses the request
SELECT 1; DROP VIEW "item-health"                         -- statement.ts: two statements
CREATE TABLE t AS SELECT 1                                -- statement.ts: not read-only
SELECT * FROM "summary-quality-evals"                     -- with only host-fingerprint selected: the engine names no such table
```

**It does not assert that `INSTALL httpfs` fails.** With no seal it may well succeed, because the extension host is one of the admitted origins - and succeeding buys nothing, since every request the loaded add-on could then make is still refused by the same policy. **An oracle that asserted a refusal we do not enforce would be a test that passes for the wrong reason** and goes red on an engine upgrade that changed nothing that matters.

**For the same reason it does not assert that a minted file name is unreadable.** `SELECT * FROM 'door/1.parquet'` reads that file: the keeper keeps every whole file it fetched registered under its minted name for the page's life, and DuckDB reads a registered file named in a `FROM`. What it reaches is rows this page already fetched and counted, so nothing rests on hiding it, and no control here claims to. The view-drop rule (section 2.4 rule 3) is about the cost a person sees, and a held file costs nothing more.

**Why the site build writes the listing.** `RawDayIndex` is declared in `backend/idhazh/contracts/ledger_index.py`: the ledger, the date, the file names in ascending order, their digest, and when they were listed. The gardener writes one to `state/raw/<ledger>/index/<YYYY-MM-DD>.json` - **but only when it packs that day**: `backend/idhazh/gardener/tasks/_index_day.py` says the compaction lists a day the moment it takes it and nothing else writes a listing. So a day not packed yet has no listing, and the browser cannot list a directory. The writer files themselves are parquet (`ledger.compression_raw` is snappy), so the engine reads them as it reads a packed file. **Row 7 has the site build write the listing** (row 7 decision 1), and row 2 gives the contract the one field the browser needs from it (row 2 decision 11).

| # | Rule about the listing | Why |
| --- | --- | --- |
| 1 | **Which days.** Per published ledger, every day after the newest day any packed index names - a day as itself, a month through its last UTC day and a year through 31 December - through the newest of those days that has a directory under `state/raw/<ledger>/`. At most `max(console.window_presets)` days are listed, counted from the day after that newest packed day. **A writer file's address is composed from a checked name.** `slice-reader.ts` composes the raw paths, as it composes the compact ones, and only from a name that matches `FILE_ID_NAME_PATTERN` in `backend/idhazh/contracts/base.py`, carried into the frontend copy of `RawDayIndex` and bound by `test_frontend_index_shapes.py`; a listing naming anything else is refused by name, as an index with a bad `covers` is (Guardrail #11). **The frontend copy requires `bytes`, one size per name**, because the site build always writes it and a listing without it can be neither priced nor checked. **A date in two tiers is a defect, not a merge.** Reading one date twice doubles every number on the answer. `filesFor()` already holds this property across the three packed periods and its docstring says so; the oracle in row 2 extends the assertion over a fixture ledger carrying packed and writer files for overlapping days.

**The writers' own files are not packed, so they cost more per day.** One request per writer file instead of one for the day: `host-fingerprint` wrote 55 files for 2026-09-30 alone (its committed listing). This is why panels stay on packed files: a panel draws on arrival for every reader, and this page fetches when an operator presses a button. `askCost()` reports the file count before the run, so the cost is visible at the moment it is chosen.

**Where the tiers disagree, the packed file wins by being the only one read.** Packing applies each ledger's own merge rule while it builds the file, so a packed day holds one row per record; the writers' files for an unpacked day hold what the writers wrote, which can be two rows of one record for a ledger whose merge rule is a cell union. **A difference that cannot be removed is printed on the page** rather than hidden: `AskResult.unpackedDays` carries the dates that came from the writers' tier, and the answer panel's note names them (section 2.11, the answer panel's note).

### 2.8 What reaches the site is capped at the widest span, not at what `state/` holds

**The publishing decision is site-wide; the cap on it is derived from config.** There is one staged tree, served at one address, and any page may fetch any of it - so this is not a per-route setting and no row here invents one. What the cap does is refuse to copy a file no page could ask for.

| # | Rule |
| --- | --- |
| 1 | The build copies, per published ledger, every compact file whose period overlaps the `max(console.window_presets)` UTC days ending on that ledger's newest packed day: the newest day any packed index names, with a day as itself, a month through its last UTC day and a year through 31 December. A period is copied whole, so the oldest day is rounded out to the coarsest file that holds it - a month file, or a whole year file once its year is packed. **The anchor is the data, never the build's clock.** The canary's packed days are fixed in August 2026 (`DATE` in `backend/utilities/build_canary_day.py`), and a cap counted back from the build's day would copy none of them from 2026-11-19 on |
| 2 | **The site's copy of each index names exactly the files the site carries.** The build stages each of the three indexes trimmed to the entries it copied, in the same `CompactIndex` shape and stamp, rather than byte for byte. A copied index that named a file the build left out would make the door report `file-missing` for a day nobody broke, and would fail `frontend/tests/published-ledgers.spec.ts`, which asks for every address an index names. The data files stay byte for byte, so a published file still cannot say anything `state/` does not. A trimmed index keeps the `CompactIndex` stamp, and `published-ledgers.spec.ts` reads every staged index through `readIndex()`, so the trimmed shape is checked against the contract the door reads |
| 3 | The writers' tier is staged only for days after the newest day any packed index names - a day as itself, a month through its last UTC day and a year through 31 December - and at most `max(console.window_presets)` of them, by row 7 (section 2.7, the listing rules) |
| 4 | **The number is read from config, never written down.** `published-ledgers.mjs` reads `console.window_presets` from `config/appearance.json`, where the key lives - the legacy `console` block in `config/idhazh.json`, the only file the script reads today, has no such key - as `build-frame-css.mjs` reads that file, and it refuses a missing key by name. | 5 | **What `state/` holds is a different question and belongs to the gardener's keep windows.** Git keeps the history; the site carries the part a reader can reach. ### 2.12 The states, and which vocabulary owns each

`frontend/src/lib/console/waiting.ts` owns `PanelState = 'ready' | 'loading' | 'quiet' | 'missing' | 'unreachable'` and `ChartState = PanelState | 'too-few'`. **Row 2 adds one member and nothing else** (Guardrail #4): `refused` joins `PanelState` and the table of states in `waiting.ts`, and `frontend/src/lib/charts/d3/empty.ts`, which re-exports each state's sentence, gains `refusedSentence`. | 1 | `loading` | `PanelState`, exists | The engine, the indexes or the files are on their way |
| 2 | `quiet` | `PanelState`, exists | The statement ran and matched no rows |
