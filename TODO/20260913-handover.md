## What a worker on row #1a must be told

The row says all of this, but a worker that skims will miss the traps. Put these in the brief.

- **JSON, as a Pydantic contract of our own.** Not a Vega-Lite spec - O4 removes that grammar and publishing it ships it to every reader forever. Not Parquet, Avro or Arrow - verified 2026-09-13, zero occurrences anywhere in the repository, and a chart has three to twelve marks.
- **The published location is `frontend/public/digest/<YYYY>/<MM>/<DD>/<item_id>.json`.** One visual, one file. The shard is the day directory.
- **The chart data never enters `digest.json`, and the prune is the reason.** The day payload is never deleted, so data inside it could never age out and `retention.image_months` would have nothing to act on.
- **`frontend/src/lib/payload/types.ts` is hand-written.** There is no TypeScript generator, no `frontend/src/contracts/` and no emitter under `frontend/scripts/`. The drift gate covers `schemas/` only. A worker who runs an export, sees no diff, and calls the file checked has proved nothing.
- **`schemas/digest-day.schema.json` already carries a `2026-09-13` stamp.** Today's stamp must be the minute form `2026-09-13T<HH>:<MM>` or `contracts/base.py` raises `TypeError` at import.
- **The row has two oracles and the second is the one that gets skipped.** One: the published data redraws the picture the old renderer drew, on a built fixture day - this is the last moment the old output and the new input can be compared at all. Two: the degrade rule - a fitting fixture and a mis-shaped fixture per type, where the mis-shaped one leaves the story shorter with no console error.
- **Row #1a deletes no `.svg` and moves no byte a reader receives.** If the worker's diff touches a committed drawing, it has left its scope.

## Dispatch discipline

- **Two to three workers per block, in ONE assistant message.** Control returns only when every call returns.
- **Do not wait for a merge to refill.** As soon as a worker returns, dispatch the next one.
- **Mark the row IN-FLIGHT with its worktree name in the same commit you push before dispatching.** Push protocol from the detached orch worktree: `git fetch origin main; git rebase origin/main; git push origin HEAD:main`. It is rejected as non-fast-forward otherwise. When the rebase conflicts on a Reckoner table because a sibling row merged, **the resolution is always to keep both lines.**
- **Verify before you dispatch.** For every path, symbol and fixture the row names: does it exist, is it spelled right. This has caught something on every row so far - seven missing paths on plan 25 row #8, four wrong entries on plan 12 row #1, a contract that does not exist on plan 19 row #1.
- **Give each worker an explicit do-not-touch list** naming the files its siblings hold. It is the only thing that has reliably kept a block collision-free.

## Collisions

`.tmp_wave.py` in the orch worktree maps them: `python .tmp_wave.py '<plan-file>.md::<row>' ...` with bare filenames.

Two caveats that will mislead you:

- **It prepends the plan-doc itself to every row's claim set**, so a CLASH whose only member is `TODO/<plan>.md` is an artefact, not a collision.
- **A row it cannot find prints `ROW NOT FOUND` and then reports `clear` against everything.** Both known-defect rows (`20260823-known-defects-plan.md` #2 and #18) do this. Never schedule on a clear verdict for a row with an empty claim set.

## Environment traps

- The venv is an editable install pointing at the **shared checkout**. Set `$env:PYTHONPATH` to your worktree's `backend` before every Python command and confirm `idhazh.__file__` resolves inside your tree.
- Wrap `ruff`, `mypy` and the contract export in `backend/utilities/gate_lock.py`. It logs "waiting for the gate lock" once and then goes quiet - a log that has not changed is queued, not hung.
- **Never wrap `npm --prefix frontend run test:changed` in `gate_lock.py`.** `run-checks.ts` takes that lock itself and self-deadlocks.
- With siblings live, a bare non-zero exit with no output means their interrupt landed in your shell. Re-run detached via `Start-Process pwsh -WindowStyle Hidden`, write the exit code to a file under `$env:TEMP`, and read the file. A detached process does not inherit the terminal's PATH - capture it first and read it back, and call `npm` as `npm.cmd` by absolute path.
- `gh pr merge` prints "could not determine current branch" from a detached worktree and **still merges**. Read `gh pr view <n> --json state,mergedAt`, never the exit code.
- Remove a worker's worktree before `gh pr merge <n> --squash --delete-branch`.

## A live defect, recorded and deliberately not patched

**The build-time renderer is not deterministic inside one process.** Vega's clip-path id counter is global, so a drawing's bytes depend on where its item sat in the render order - 495 drawings carry 3,256 clip ids running `clip1` to `clip67`. The determinism test in `backend/tests/test_render.py` cannot see it: its spec has no title, so it emits no clip path and passes for the wrong reason. Both are written into [`../docs/architecture/publishing/visuals.md`](../docs/architecture/publishing/visuals.md). Not patched, because plan 12 row #1b deletes the module and a fix inside a module being deleted is the temporary kind Guardrail #5 refuses.
