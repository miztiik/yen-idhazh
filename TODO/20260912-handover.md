## Do not wait for a merge

`runSubagent` is synchronous, so one orchestrator cannot run two workers at once. That is a real limit and it is not the one that wastes time. **What wastes time is waiting for a merge before setting up the next row.** Three levers, in order of how much they buy:

1. **Dispatch on green, not on merged.** The moment a pull request's checks pass, stamp the next row, cut its worktree and dispatch. Merge the previous one while the next worker is already reading. A merge takes seconds; a worker takes many minutes.
2. **Stack a dependent row on the branch below it.** When row B depends on row A and writes the same files, cut B's worktree from **A's branch** rather than from `origin/main`, and open B's pull request with `--base <A's branch>`. GitHub retargets B to `main` the moment A merges. This is the only way to start B before A lands without guaranteeing a conflict.
3. **Hand a disjoint row set to a second agent session.** This is the one that actually parallelises, because each session is its own orchestrator. **29 rows can start now.** Before splitting, check that the two sets write no file in common - a plan row's `Files touched` bullet is the input, and a glob in that bullet hides a collision rather than avoiding one.

**What you may not do:** cut two worktrees that write the same file from the same base. Today's chain shares `classify/calls.py`, both prompt files, `test_classify.py` and `test_summarize.py` across three consecutive rows, so those three were run in order on purpose.

## Traps that cost time today, all now written into `docs/`

- **`state/*.csv` is `merge=union`, and a merge never conflicts on it.** A branch that widens a ledger header gets both headers stacked silently. Worse, the pipeline appends faster than a CI cycle finishes, so "repair and wait for green" never converges. The repair recipe and when it is legitimate to merge on `UNSTABLE` are in [`../docs/reference/agent-notes/git-and-github.md`](../docs/reference/agent-notes/git-and-github.md).
- **`TODO/STATUS.md` has one writer now** - a `status-page` job on `main`. A pull request that carries the file fails `gates`. Stamp your Reckoner line and leave the generated page alone; if a merge drags it in, `git checkout origin/main -- TODO/STATUS.md`.
- **`gh pr merge --delete-branch` exits 1 from a detached worktree after merging successfully.** Read `gh pr view <n> --json state,mergedAt` rather than the exit code.
- **A plan row's numbers go stale in a day.** Both pre-dispatch checks in [`../docs/how-to/execute-a-plan.md`](../docs/how-to/execute-a-plan.md) earned their cost today: row #7a of plan 23 was wrong about three figures and row #6 of this plan was wrong about four names, including the name of the CI job it deletes.
