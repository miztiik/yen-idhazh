## 2. Row #1 - Build name-and-figure tables from an article

- **Scope:** A function with no model in it turns one article's text and element table into tables of name-and-figure rows. Nothing calls it yet.
- **Files touched:** New: `backend/idhazh/classify/pair_names_with_figures.py`, `backend/tests/test_pair_names_with_figures.py`. Nothing else: it reads the table, the text and `visuals` as they are.
- **Acceptance gates:** Local: the new test file; ruff and mypy over `backend/`. CI: the complete suite.
- **Oracle:** In memory, with no model and no network. One table of four rows: the wind page (four countries, four figures in MW, across three sentences). One table a unit from a sentence that gives each name two figures. A unit the service labelled a name, a number inside a name, a name inside a longer name and a long name cut as the chart cuts it do not break a table. No table: a repeat of a name that hides a pair (`Germany is in Europe. Denmark said Germany built 1,200 MW.`), two names then two figures (`Denmark and Germany approved 1,200 and 900 MW.`), a name with two figures of one unit, a figure before the first name, a neighbouring sentence that names something and holds a figure it cannot pair, a name with a line break or `|`, two names the label cut makes equal, figures with no unit, two units in one run, a name twice in one run, a run under the floor or one row over the ceiling, `visuals.enabled_kinds` empty, and `visuals.enabled_types` holding neither bar nor dot. Then once, in a scratch script that is not committed: rebuild each chart-asking article of digest runs 44259308561, 44232477603 and 44223473759 from its saved prompt (the `captures-*` artifacts, retained to 2027-02-16; a prompt holds the article and its element rows), build the tables, and list every table in the pull request beside its sentences. The worker marks each table twice: pairing right or wrong (read off the sentence), and worth a chart or not (at least `visuals.min_chart_points` figures of one kind compared across names); the user may overrule any mark. Wrong pairings must be zero; one found is fixed by tightening the rule, and the check is run again. It cannot settle that the model picks well from the tables, or pairing in a sentence whose figure belongs to a referent the service did not label ("it", "the firm").
- **Decisions:**

Table D - Row #1 decisions

| ID | Decision |
| --- | --- |
| D1 | Pairing, one sentence at a time. A name takes the figures after it up to the next name: its block. For one unit, a sentence pairs only when every name in it has exactly one figure of that unit in its block, no figure of that unit comes before the first name, and nothing in it overlaps; any other sentence pairs nothing for that unit. Names are every occurrence of an entity or place element's words in the text, matched on whole words, because a repeat is not an element and the table alone would hide it. A name inside a longer name is not a second name; a name inside a figure, or a figure starting inside a name, gives way to the other. A wrong pair is worse than a missed one, so there is no distance limit and no figure-before-name reading: each would be a new rule, added only if the check shows real tables lost without it. The check did show the plain name, figure, name, figure reading losing real tables, because a name is often followed by two figures of different units (a share move and a price, a capacity and a tariff), so each unit is read on its own |
| D2 | A table is a maximal run of consecutive sentences that each pair for one unit that is not null (a byline or a page number has none). A run is refused when the sentence just before or after it names something and holds a figure of that unit it could not pair, because the list may go on there; a sentence that names nothing is not a list. A run is kept only when its names are all different and its row count is at least `visuals.min_chart_points` and at most the smaller of `visuals.max_chart_points` and the plan's limit on ids in one channel; over the ceiling the run is refused whole, never trimmed (Andre) |
| D3 | Every table is offered as the enabled types among bar and dot: the two forms whose marks are one name and one figure and that need no stated whole. Both mean purpose `comparison`. A test pins each to the validator's role table. The offer is therefore one line for the request, and no table carries its own forms. None enabled means no table |
| D4 | A cell is offered only when it is one line, holds no `|` and is unchanged by `sanitize`; a run with a cell that fails is refused whole, because a line break or `|` would let a name forge a row. A name is shown as the chart will draw it, cut to `visuals.max_label_characters` the way the compiler cuts it, and a run whose cut labels are equal is refused whole. A row carries that label, its name element (the first occurrence) and its figure element so code can build a plan later; the model is shown only the row code, the label and the figure's words. Row codes r1, r2, ... run across all tables in article order |

Table E - Row #2 decisions

| E1 | Reply: `visual` holds `why`, `type`, `focus`, `title`, `caption` after `summary`, which still decodes first so a cut reply keeps it. The rules say: write the reason in words with no digits; choose a chart only when the item is about how the figures in one table compare across names; choose none for separate facts, passing mentions, and figures that measure different things for different names; check the table against the item and not the summary; never write a figure that is not in the table; the title is short, factual and has no digits; one worked chart answer and one worked none answer (Andre) |
