## 1. The route job still times out, and now we know exactly why

**This is the highest-value item on the list and it is close to closed.**

Run `32804437110` ran on 2026-08-25 at commit `2aa03f5`, which carries every fix
from PRs #63 and #67. `route` was **still cancelled at 60.3 minutes**.

That is not a failure of the fix. It is the fix behaving exactly as designed and
yielding nothing, for a reason that is now measured rather than guessed.

### What the run measured

| What | Value |
| --- | --- |
| Fixed cost (checkout, Python, cache, llama-server start, install, artifacts) | **47 s** (05:04:46 -> 05:05:33) |
| `Route and render` | cancelled after **59.4 min** |
| Items routed | 88 |
| Items the gate skipped | **0** |
| Per-item | mean **40.3 s**, min 12.5 s, max 76.5 s, n=88 |
| Model draft kinds | 71 `none`, 17 `chart`, **0 `diagram`** |
| Charts that survived the post-model controls | 9 of 17 |

### The open question from PR #63 is now answered

`docs/architecture/publishing/visuals.md` says the diagram arm's zero production
rate had three possible causes and nothing committed could tell them apart. The
draft-kind logging added in PR #63 settles it:

**The model drafted `diagram` zero times in 88 items.** It is not
`min_diagram_steps` rejecting short answers - the model never asks for a diagram
at all. Combined with the earlier count (0 diagrams in 149 routed and 0 in 586
published on 2026-08-24), that is 237 routed items and zero diagram drafts.

### What to do

Set `visuals.enabled_kinds` to `["chart"]` in `config/idhazh.json`.

That single config edit unlocks the entire gate: with `diagram` off, every item
whose facts hold no unit group of at least `min_chart_points` skips the model
instead of spending 40 seconds proving a settled question. On the 2026-08-25
population that is most of the 71 `none` drafts.

**This is Jony's call, not an engineering one** (`docs/agents/guardrails.md`
authority table: chart vs diagram vs nothing). Dispatch the Jony persona with the
0-in-237 evidence and the 40.3 s per-item cost, and let the ruling decide. If
Jony wants the arm kept, the honest alternative is to fix the prompt first - it
carries a chart exemplar and a `none` exemplar and no diagram exemplar, and it
states a base rate on the `none` arm at `temperature: 0.0`, where a stated prior
is a deterministic argmax flip rather than a nudge.

Either way, **do not raise `timeout-minutes`** (Rule #2).

### Measure the yield offline before you ship it

`numeric_facts` is pure - no model, no network, no runner. Over a day's committed
article JSONs, histogram `max(Counter(f.unit for f in facts).values())` at
`limit=16` and count how many fall below `min_chart_points`. That tells you
whether the gate alone clears 60 minutes before you spend a run finding out.
Rule #10 forbids estimating what is this cheap to measure.

## 2. A cancelled route job throws away the charts it already rendered

**One line, high value, nobody has done it.**

`.github/workflows/digest.yml`, the `routes` upload step (around line 426):

```yaml
      - uses: actions/upload-artifact@v7
        with:
          name: routes
```

It has **no `if: always()`**, unlike the `Upload router log` step immediately
above it. So when `Route and render` is cancelled at the bound, the artifact
never uploads and `assemble` receives no routes.

On 2026-08-25 the router rendered **9 charts** and every one was discarded. The
published day carries **145 items and zero visuals**, and `frontend/public/digest/2026/08/25/`
holds zero SVG files.

Per-item writes are atomic (temp-then-rename), so whatever finished is valid.
`always()` does run on cancellation. Adding it salvages the partial work and is
what "degrade, do not fail" (`CLAUDE.md` section 1a) asks for at this boundary.

While you are there: `route` carries `continue-on-error: true` so the day
publishes either way, but **nothing on the page tells a reader the visuals are
missing**. Defect 10's original note called that out and it is still true.
Whether the page should say so is a Jony and Reader question.

## 3. The per-item route cost doubled and nobody knows why

| Date | Run | n | Mean | Min | Max |
| --- | --- | --- | --- | --- | --- |
| 2026-08-24 | `32742672105` | 148 | **21.0 s** | 8.1 s | 56.0 s |
| 2026-08-25 | `32804437110` | 88 | **40.3 s** | 12.5 s | 76.5 s |

Two observations, one changed variable nobody controlled. Rule #10 says this may
not justify a design decision in either direction.

Things it is **not**: `visuals.request_timeout_minutes` is 2.0 (120 s) and the
slowest item was 76.5 s, so nothing was cut short. `lead_words` is unchanged at
its default 150.

Candidates worth separating: article length that day, runner hardware variance,
and prompt-cache behaviour across items. The `router-log` artifact holds
llama-server's own `print_timing` lines - read prefill against decode there
before theorising. Prefill is most of each request and the fact menu plus the
150-word lead is most of the prefill, so `visuals.lead_words` is an untested
lever that PR #63 put in config precisely so it could be swept.

## Traps that cost time

- **A background process can fast-forward your feature branch mid-session.**
  Observed 2026-08-24: `git worktree list` showed a commit nobody authored.
  `git reflog -8` distinguishes the benign case (`merge origin/main: Fast-forward`)
  from the dangerous one (`checkout: moving from X to Y`, a parallel agent
  switching branches under you). Commit early once work is green.
- **`gh pr checks` can report "no checks reported"** on a freshly opened PR whose
  CI never triggered. Rebasing onto current `origin/main` and pushing re-triggers
  it. A PR opened against a stale base will conflict on `app_config.py`'s
  changelog - resolve by keeping both entries, newest first, then regenerate
  `schemas/` with `python -m idhazh.contracts.export` rather than hand-merging the
  generated file.
- **The rest live in** [`../docs/reference/agent-notes.md`](../docs/reference/agent-notes.md)
  and the trap list in [`../docs/how-to/run-the-gates.md`](../docs/how-to/run-the-gates.md).
  Read both before running the browser suite.
