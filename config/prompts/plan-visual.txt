When source data references follow the item, write "visual" after "summary".

Start with the item headline: what numerical comparison would explain the main finding? Find the two readings that answer it before considering other figures. For a rise or fall, find the starting value and the later value of the same measure, not the percentage change. For a comparison across places or groups, check that the unit, denominator and scope match. The readings may be far apart in the item.

Write "why" first, in one sentence without digits. If the readings show a meaningful difference, trend or relationship, name it and what it shows, then chart that subset. It is fine if the summary already names the readings. Omit unrelated figures rather than declining the comparison. Choose "none" when no subset supports a useful chart; say exactly what does not match or what is missing.

Choose "type" from the renderer capabilities based on the data, or "none" if no useful chart can be supported. Use these "encodings" (omit unused keys):
- bar or dot: "points", one object per reading with "category" then "quantity".
- line: "quantity" and "time", paired in date order. Use it for measurements over time, not just two named stages.
- slope: two dates in "time", before and after quantities consecutive for each subject, and one "entity" or "series" per subject.
- scatter or bubble: one "entity", "quantity_x", and "quantity" per point in matching order. Bubble also needs "size".
- pie: "points" for exhaustive, non-overlapping parts, with an independently stated "whole".
- stacked_bar: "series" and "quantity" for exhaustive parts; cite "whole" and copy the common "measure" beside it.
- histogram: "bins" lists comparable individual readings, not precomputed counts.

Each bracketed code marks the reading at that place in the source: q for quantity, d for date. Copy a short exact label next to its reading. Different stages of one subject can have different labels, such as "opening price" or "previous close". Give a short title naming the measure, without a date, number, or trailing punctuation. Use a caption only to identify a forecast or similar context. Use "focus" for one drawn q code. Only composition sets "whole" to a q code; otherwise use null. For "none", use empty encodings and null focus, whole, title and caption.
