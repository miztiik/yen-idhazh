When source data references follow the item, write "visual" after "summary".

Start with the item headline: what numerical comparison would explain the main finding? If the story leads with a single change from one level to another, use the two actual readings that establish that change. Omit the percentage change and old targets; do not plot a range as one of its endpoints. If the story tracks a trend over several dates, use the comparable readings across those dates. For a comparison across places or groups, check that the unit, denominator and scope match. The readings may be far apart in the item.

Write "why" first, in one sentence. Name the things being compared, their shared measure, and what the reader will see. Use words, not values or placeholders. If the source explicitly compares the readings on the same basis as part of the main finding, use them even if the summary already reports the comparison. Exclude unrelated readings. Use "none" only if the main finding has no useful comparable readings; explain what does not match or what is missing.

Choose "type" from the renderer capabilities based on the data, or "none" if no useful chart can be supported. Use these "encodings" (omit unused keys):
- bar or dot: "points", one object per reading with its q code in "quantity" followed by one of that reading's label codes in "category".
- line: "quantity" and "time", paired in date order. Use it for measurements over time, not just two named stages.
- slope: two dates in "time", before and after quantities consecutive for each subject, and one "entity" or "series" per subject.
- scatter or bubble: one "entity", "quantity_x", and "quantity" per point in matching order. Bubble also needs "size".
- pie: "points" for exhaustive, non-overlapping parts, with an independently stated "whole".
- stacked_bar: "series" and "quantity" for exhaustive parts; cite "whole" and copy the common "measure" beside it.
- histogram: "bins" lists comparable individual readings, not precomputed counts.

Each bracketed code marks the reading at that place in the source: q for quantity, d for date. In "points", choose the code for the complete name or stage, not a generic word near it. If a number is repeated, cite the occurrence beside its complete label. Use "began trading", not just "trading". Use "West Bay", not "Bay". For entity or series labels, copy source words verbatim. Give a short title naming the measure. Use a caption only to identify a forecast or similar context. If your title or caption names a date not on the chart axis, cite its d code in "context"; otherwise omit "context". Use "focus" for one drawn q code. Only composition sets "whole" to a q code; otherwise use null. For "none", use empty encodings and null focus, whole, title and caption.
